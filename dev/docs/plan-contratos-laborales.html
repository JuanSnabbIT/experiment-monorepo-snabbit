Sección 5

Tabla de Riesgos

Riesgo Probabilidad Mitigación
Cálculo de fecha_termino incorrecto en meses que cambian de año o en meses con diferente número de días (ej. 31 enero + 1 mes = ?) MEDIA Usar date-fns addMonths() en lugar de lógica manual. Agregar tests con casos borde: ene→feb, dic→ene, año bisiesto. Validar también en backend (ContratoTrabajadorWriteSerializer).
Catálogo de cargos vacío en empresas nuevas sin contratos previos: el SelectCreatable no muestra sugerencias ALTA El campo siempre debe admitir creación libre (isCreatable=true) independientemente de si hay opciones. El catálogo crece con el uso. Documentar al equipo de soporte.
Regresión en selección de trabajador: al cambiar el label de {email} a {RUT}, usuarios sin RUT registrado quedarían sin identificador visible MEDIA Usar RUT como primer fallback, luego email: `${nombre} - ${rut ?? email}`. Verificar en UI que ninguna opción quede vacía.
Empresa sin email de contacto configurado al momento de enviar al empleador (campo vacío en BD) MEDIA En backend, antes de enviar: validar que empresa.email_contacto no sea nulo. Si está vacío, retornar advertencia en respuesta (no error 400). En frontend, mostrar alerta informativa.
Conflicto de migración al agregar campos JSON null en tabla con muchos registros en producción PostgreSQL BAJA Todos los nuevos campos usan null=True, blank=True, default=list/None. La migración no bloquea tabla. Hacer backup previo en producción. Probar en staging primero.
Estado del wizard no persiste la dirección de sucursal entre pasos si el usuario navega hacia atrás y cambia la sucursal MEDIA En StepTerminosLaborales, usar useEffect que observe formik.values.trab_sucursal_id: si cambia y lugar_trabajo aún coincide con la dirección anterior, actualizarlo. Si el usuario lo editó manualmente, no sobreescribir.

class CargoCatalogo(ModeloBase):
    """Catálogo de cargos por empresa. Crece con el uso del selector."""

    empresa = models.ForeignKey(
        "empresas.Empresa",
        on_delete=models.CASCADE,
        related_name="cargos_catalogo",
    )
    nombre = models.CharField(max_length=150)
    activo = models.BooleanField(default=True)

    class Meta:
        unique_together = [("empresa", "nombre")]
        ordering = ["nombre"]

    def __str__(self):
        return self.nombre


class TurnoPredefinido(ModeloBase):
    """Turnos estándar administrables. Seed: Mañana / Tarde / Noche."""

    empresa = models.ForeignKey(
        "empresas.Empresa",
        on_delete=models.CASCADE,
        related_name="turnos_predefinidos",
        null=True, blank=True,
        help_text="Null = global para todas las empresas"
    )
    nombre = models.CharField(max_length=100)       # "Turno Mañana"
    hora_entrada = models.TimeField()                # 07:00
    hora_salida  = models.TimeField()                # 15:00
    activo = models.BooleanField(default=True)

    class Meta:
        ordering = ["hora_entrada"]

2 · Lógica enviar_al_empleador en el ViewSet

Python · DRF ViewSet backend/rrhh/views.py — acción crear_con_trabajador 
@action(detail=False, methods=["post"], url_path="crear-con-trabajador")
def crear_con_trabajador(self, request):
    ser = CrearContratoConTrabajadorSerializer(data=request.data)
    ser.is_valid(raise_exception=True)
    data = ser.validated_data

    # ── 1. Obtener o crear UsuarioEmpresa ─────────────────────────────
    with transaction.atomic():
        ue, empresa_cliente = _resolver_usuario_empresa(
            data["trabajador"], request.user
        )

        # ── 2. Crear contrato ─────────────────────────────────────────────
        contrato_data = {**data["contrato"], "usuario_empresa": ue}
        contrato_ser = ContratoTrabajadorWriteSerializer(data=contrato_data)
        contrato_ser.is_valid(raise_exception=True)
        contrato = contrato_ser.save(creado_por=request.user)

        # ── 3. Notificar al empleador si corresponde ──────────────────────
        enviar = data.get("enviar_al_empleador", True)
        invitacion_enviada = False
        if enviar and empresa_cliente:
            email_destino = getattr(empresa_cliente, "email_contacto", None)
            if email_destino:
                send_contrato_al_empleador.delay(   # Celery task
                    contrato_id=contrato.id,
                    email_destino=email_destino,
                )
                invitacion_enviada = True

    resp_ser = ContratoTrabajadorSerializer(contrato)
    return Response({
        **resp_ser.data,
        "invitacion_enviada": invitacion_enviada,
    }, status=status.HTTP_201_CREATED)

4 · Cálculo automático de fecha_termino desde cantidad_meses

TypeScript · React frontend/src/pages/RRHH/components/trabajador/StepTerminosLaborales.tsx 
import { addMonths, format, parseISO } from 'date-fns';

// ── Función pura, testeable ────────────────────────────────────────────────────
const calcularFechaTermino = (
    fechaInicio: string,
    meses: number
): string => {
    const base = parseISO(fechaInicio);
    const resultado = addMonths(base, meses);
    return format(resultado, 'yyyy-MM-dd');  // ISO para el campo date
};

// ── Opciones del selector (1-24 meses) ────────────────────────────────────────
const MESES_OPTS: TSelectOption[] = Array.from({ length: 24 }, (_, i) => ({
    value: String(i + 1),
    label: i + 1 === 1 ? '1 mes' : `${i + 1} meses`,
}));

// ── En el componente, cuando cambia cantidad_meses ────────────────────────────
{values.tipo_contrato === 'plazo_fijo' && (
    <SelectReact
        name="cantidad_meses"
        options={MESES_OPTS}
        isCreatable          // permite ingresar número personalizado
        placeholder="Duración en meses"
        value={MESES_OPTS.find((o) => o.value === String(values.cantidad_meses)) ?? null}
        onChange={(opt) => {
            const meses = Number((opt as TSelectOption)?.value);
            setFieldValue('cantidad_meses', meses);
            if (values.fecha_inicio && meses) {
                setFieldValue(
                    'fecha_termino',
                    calcularFechaTermino(values.fecha_inicio, meses)
                );
            }
        }}
    />
)}

5 · Selector multi-días de semana en StepJornada

TypeScript · React frontend/src/pages/RRHH/components/trabajador/StepJornada.tsx 
const DIAS_SEMANA = [
    { key: 'lunes',     label: 'L' },
    { key: 'martes',    label: 'M' },
    { key: 'miercoles', label: 'X' },
    { key: 'jueves',    label: 'J' },
    { key: 'viernes',   label: 'V' },
    { key: 'sabado',    label: 'S' },
    { key: 'domingo',   label: 'D' },
] as const;

// ── En el componente ──────────────────────────────────────────────────────────
const diasActuales: string[] = values.dias_semana ?? [];

const toggleDia = (key: string) => {
    const next = diasActuales.includes(key)
        ? diasActuales.filter((d) => d !== key)
        : [...diasActuales, key];
    setFieldValue('dias_semana', next);
};

// ── JSX ───────────────────────────────────────────────────────────────────────
<div className="flex gap-2">
    {DIAS_SEMANA.map(({ key, label }) => (
        <button
            key={key}
            type="button"
            onClick={() => toggleDia(key)}
            className={classNames(
                'w-9 h-9 rounded-full border-2 text-xs font-bold transition-all',
                diasActuales.includes(key)
                    ? 'border-blue-500 bg-blue-500/20 text-blue-400'
                    : 'border-zinc-700 text-zinc-500 hover:border-zinc-500'
            )}>
            {label}
        </button>
    ))}
</div>
